NetHealth

Internet-health monitor — architecture & data flow

System Overview

NetHealth watches every network connection the Mac has — e.g. Ethernet → Starlink and Wi-Fi → fibre at the same time. Each link becomes a NetworkConnection with its own targets (that link's router, the optional Starlink dish, Cloudflare), probed once a second with sockets pinned to that interface, plus a periodic bandwidth test. The UI stacks one panel per connection, each with its own time-scrolling aurora ribbon. Pure SwiftUI / MVVM, zero external dependencies.

Connections: one default route per interface

With two live links macOS keeps two IPv4 default routes. The primary one is unscoped; the other carries RTF_IFSCOPE and is used only by sockets bound to its interface. So discovery reads every default route, and every probe binds to its link — without that, all probes would silently measure the primary link.

Pinning. BSD sockets use setsockopt(IPPROTO_IP, IP_BOUND_IF, ifindex); Network.framework uses NWParameters.requiredInterface. Both work inside the App Sandbox. URLSession has no public equivalent, which is why the bandwidth test speaks HTTP/1.1 over NWConnection itself.
Local link rate. No traffic is sent to the router (its only web server is a ~5 KB admin page, so it can't be a speed-test endpoint). Instead LinkReader asks the OS: CoreWLAN for Wi-Fi transmit rate, band, channel, width, RSSI and noise; if_data.ifi_baudrate for Ethernet speed. Shown as a chip in each panel header, amber when on 2.4 GHz or when the last download reached ≥60 % of the link rate (the local hop is the bottleneck). Sandbox-safe; only the SSID would need Location permission, and it isn't read.

Bandwidth test

On a schedule (default every 10 min, first run ~5 s after launch; Off / 1 / 5 / 15 min / hourly from the header menu) or on Test now, each connection is tested in turn: download then upload against Cloudflare, six parallel TLS streams, stopping at 3 s or the byte cap. The test span is recorded as a SpeedWindow and shaded on that link's graph so latency-under-load is visible.

Measurement. Each direction stops at the first of 3 s after first byte, 40 MB ↓ / 15 MB ↑, or all streams done. The rate skips the first 25% (≤ 0.5 s) to exclude TCP slow-start. Cloudflare rejects single requests over 100 MB (403) and, after heavy testing, answers 429 to single downloads of ≥ 10 MB — so each download stream loops 4 MB requests on one keep-alive connection. Any remaining 429 backs that link off.

The probe loop

Every second the view model fires every connection × target concurrently in a TaskGroup so a slow or lost host never delays the others, stamps the batch with one shared timestamp (so the ribbons stay time-aligned), and appends a PingSample to each target's rolling history.

Measurement: ICMP → TCP fallback

Real ICMP echo is tried first, but the macOS App Sandbox lets the app create and send on an unprivileged ICMP datagram socket while denying the inbound reply with EPERM. The service detects that once and permanently falls through to a TCP connect-time probe — the SYN→SYN/ACK round trip, a close proxy for ICMP RTT. Each reading is tagged with the method that produced it (Reading(rtt, method)), which surfaces as an ICMP/TCP badge on every stat card.

Why TCP connect time? It needs no special privilege, works inside the sandbox with only network.client, and a connection-refused on a closed port is effectively instant — so trying a few candidate ports per host is cheap. The per-card badge shows which path is live — on a sandboxed build every card reads TCP.

Rendering: the time-scrolling ribbon

The graph is a single SwiftUI Canvas redrawn at 60 fps by a TimelineView. Points are positioned by their real age (now − sample.date) across a fixed 90 s window, so the ribbon scrolls continuously rather than compressing. The leading edge is pinned to the right so the trace glides smoothly instead of sawtoothing as each sample lands.

Targets

NameHostProbe portsMeaning
Routerthat link's gateway80, 443, 9000LAN gateway — local hop (real default route, e.g. 192.168.1.1 on Starlink, 192.168.108.1 on fiber)
Dish192.168.100.180, 443Starlink dish (user terminal) — optional; omitted when unreachable
Cloudflare1.1.1.1443, 80Public-internet anchor
Any network, not just Starlink. Gateway.defaultIPv4() reads the kernel routing table via sysctl(NET_RT_DUMP) — the in-process equivalent of route -n get default, and sandbox-safe — so the Router target points at whatever gateway the machine is actually behind. Optional targets (the dish) are only shown once they've answered at least once (TargetHealth.everReachable), so a missing dish is omitted from the cards, the graph, and the overall-health tint rather than dragging the window to "Offline". And because a ECONNREFUSED RST is a full round trip from a live host, TCPPinger counts it as a reading — letting a bare gateway with no open web port still read as a healthy local hop.
The dish is probed gently. Its gRPC management port 9200 is deliberately left out — a plain TCP connect on the web ports is enough to time the local hop, and the dish's Handle API endpoint also accepts reboot/stow, so NetHealth never speaks to it. Polling that API too hard appears to be able to crash the dish.
